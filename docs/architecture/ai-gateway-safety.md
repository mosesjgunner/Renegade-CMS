# AI gateway safety and usage

The AI gateway is optional. With no active, compatible connection or budget, ordinary editorial work continues and the caller receives an explicit recoverable state. It returns proposals only; applying a proposal remains a separate human/editorial workflow action.

Tasks are registered in `src/modules/ai/contracts.ts` with a capability, input allowlist, output shape, timeout, context ceiling, permission, audit requirement, sensitive-data rule and fallback. The inspected context preview identifies exactly which article, selection, brand voice, sources and visible post IDs were supplied. Private editorial notes are rejected by the gateway; they are not a provider input.

Imported material, source text and discussion posts are data rather than instructions. The gateway directs models not to acquire authority or use tools, sends only public published discussion posts, validates proposal shapes, redacts provider diagnostics and never retries a request implicitly. Cancellation and provider failure leave drafts unchanged. Usage tokens and a configured estimate are returned with every successful proposal; per-task and monthly budgets are enforced before execution and high-cost responses are withheld.

OpenAI-compatible endpoints are the first adapter, covering OpenAI-compatible BYO endpoints and Qwen-compatible deployments. A local Ollama adapter is included because it is directly testable over its documented local HTTP contract. Gemini is deliberately deferred: this repository has no Gemini SDK or provider contract test evidence, so adding it would be an unverified provider-specific surface.

Agents must use reviewed `ToolManifest` entries with explicit grants and scope checks. They may propose/read only in their own Site, Publication and Space. Publishing, scheduling, permissions, provider connection changes, bulk delivery, social posting, spending, anchoring, moderation and external imports have no AI agent tool in this milestone.

## Operator and editor workflow

Operators use `/admin/ai` to save a site or publication scoped connection. Set `AI_CREDENTIAL_KEY_BASE64URL` to a persistent 32-byte base64url key before saving credentials. The API key is stored as an AES-256-GCM envelope in the restricted `ai-credentials` collection. The connection projection and audit never include the envelope or clear key. Keep the encryption key stable across restarts. Key rotation requires a planned re-encryption procedure before changing the key.

Only `ai.openai-compatible` and `ai.ollama` may be configured. OpenAI-compatible endpoints require HTTPS and must advertise the chosen model from `/models`; local Ollama is restricted to literal loopback HTTP and `/api/tags`. A connection test sends a bounded text probe and a separate JSON probe. Its capabilities list contains only successful probes. A failed test leaves the connection degraded; disabling it removes it from the editor's active choices. URL shape alone does not establish compatibility. The adapters support text and JSON proposals, not visual inspection or image generation. Media alt text suggestions use existing metadata only.

Editors preview the exact outbound context before requesting a proposal. The four wired tasks are writer revision of one complete draft text node, Discovery title and description, governed image alt text from metadata, and copy variants for a Distribution draft. The server loads each target and verifies its site, publication, lifecycle, and source visibility. Writer apply changes the canonical Content rich text, invoking the editorial revision hook. The other apply actions update only their owning fields. Published Content and non-draft Distribution variants cannot be changed by these AI actions. Decline leaves the target untouched. Each decision records actor, time, target, status, and applied fields; writer application also records the new revision ID.

Token ceilings and configured cost estimates are checked before dispatch. A database lease permits one call per connection and charges the maximum estimated cost against the monthly allowance before sending it. Known actual usage replaces the reservation after completion; an unknown, failed, cancelled, or interrupted call retains its conservative charge. A crashed lease expires after one minute, while its charge remains for operator review. The usage view shows provider reported tokens and the configured estimate, not an invoice. Provider token accounting and price settings must be checked by the operator.

Provider failure, timeout, cancellation, no provider, exhausted budget, and busy connection return distinct recoverable states. No proposal is applied by a provider response. Imported and source material remain data inside a system instructed provider request; schema validation removes unapproved structured fields, and all output still requires human review. The browser journey in `tests/browser/ai-proposal-workflows.spec.ts` exercises a deterministic local Ollama HTTP contract, not a live external provider. A real provider must pass the operator connection test in its deployment environment.
