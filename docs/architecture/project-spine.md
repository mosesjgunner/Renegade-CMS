# Project spine

- **Target users:** independent publishers, creators, small editorial teams and organizations that want a capable site without surrendering their data or identity to a hosted platform.
- **Promise:** publish durable, professional work from one calm, self-hostable system while adding optional audience, community and business capabilities without making them prerequisites for reading.
- **Core loop:** capture a draft -> edit and review -> publish a canonical record -> present it through a theme -> distribute deliberately -> learn from first-party evidence -> revise with history intact.
- **Ownership and portability:** operators control deployment, PostgreSQL data, media and secrets. Stable IDs and versioned export contracts must let content, relationships and provenance leave the product without scraping rendered pages.
- **Renegade Party boundary:** Renegade Party is the first production publication and a native theme. It may configure or consume public platform contracts; no core module, migration, fixture or required runtime setting may depend on its name, politics or visual identity.
- **First production vertical slice:** configure one publication/site, create and review an authored article, publish it at a stable URL, render it in the native theme, expose correct metadata/feed entries, and export it with authorship and revision provenance. M01 proves only the executable platform path underlying this slice.
