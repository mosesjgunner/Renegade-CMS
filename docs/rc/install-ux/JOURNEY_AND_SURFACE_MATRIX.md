# RC3-UX-INSTALL-01 — Journey and surface matrix

Scope actually covered by this pass: the install → setup → recovery spine
and the status surfaces inside it. Everyday-workflow surfaces outside this
spine (publishing loop, media, community, commerce, social) are owned by
their subsystem passes; onboarding/presentation surfaces are owned by the
System 2 v1.2 program (see the handoff list in the evidence log).

## The beginner funnel, counted (browser setup, provisioned install)

1. Open `/setup` (link from the installer's final message / claim handoff).
2. Paste the one-time token, confirm email — 2 inputs.
3. Name the site — slug, URL, locale, timezone are pre-filled or derived —
   1 required input.
4. Pick a look (default preselected) — 0 required inputs.
5. Site features (default preselected from the installed profile); provider
   status is shown, not asked — 0 required inputs.
6. Review → create passkey (one device prompt).
7. Save recovery codes (copy/download + one checkbox) → Open Admin Studio.

Required human decisions on the default path: token, email, site name,
passkey prompt, recovery acknowledgment. Everything else has a default
that can be accepted.

# Continuation (Nov 19, 2026) — complete operator-surface inventory (UXI-01 remainder)

Method: every `page.tsx` under `src/app/(frontend)/`, `src/app/(embed)/`,
and `src/app/(payload)/admin/` was enumerated from the filesystem at base
`8e9220e` (69 page files), each page component was read, and delegated
components were followed one level. Entry points were established by a
repo-wide search of `href`s, starter/navigation definitions
(`src/modules/starters/`), and generated URLs (email builders, API
responses, provider return URLs). API routes are listed by group, not per
endpoint: 236 `route.ts` files under `src/app/(frontend)/api/` in 24
top-level groups (plus the Payload REST/GraphQL catch-alls under
`src/app/(payload)/api/`, which serve `/api/<collection>` reads such as
the Builder's `/api/page-layouts/<id>`).

Counts: 69 page surfaces inventoried; 8 surfaces have **no inbound link
from outside their own route subtree** (see §7); 3 dead controls found,
all on one surface (`/pos`); 3 preview-only/placeholder surfaces
(`/pos`, `/graphics-studio`, `/social-studio`).

State key: **L** loading, **E** empty, **X** error, **O** offline —
"present" means the component code renders that state. Server-rendered
pages have no client loading state; their error surface is `notFound()`
plus the shared `src/app/(frontend)/error.tsx`. "—" = not present in the
inspected code. Verdict: **Real** = primary action works end to end per
the code (server query or API call that persists/returns real data);
**Preview** = honestly labelled preview with no persistence;
**Dead** = controls that do nothing or restate existing state.
