# Creator Studio operations

## Deploy and roll back

Use [Production Deployment](../PRODUCTION_DEPLOYMENT.md) and pin the web, worker, and media images to an identified release. Before promoting, record the image digests, active modules, worker profiles, storage locations, migration ledger, and last verified backup. Check the web readiness endpoint, worker health, and an actual scheduled publication after deployment. Keep the previous image and configuration together. Use image rollback only when the migration ledger is unchanged. After a schema change, use the tested recovery path in [Operational Backup](../OPERATIONAL_BACKUP.md).

Keep the core web and PostgreSQL services on the primary profile. For isolation, enable the `media-worker` profile and verify its heartbeat before setting `WORKER_DELEGATE_MEDIA=true` and recreating the main worker. The ordinary media worker runs one job at a time. The separate `media-heavy` profile runs only its heavy queue, with one slot by default and a maximum of four per process. Enable `email-account` where password reset delivery needs a dedicated worker. For rollback, turn off media delegation and recreate the main worker before stopping the ordinary media worker. Stopping the heavy worker pauses heavy work. Inspect durable job states before retrying failed or interrupted jobs.

Pause optional account, media, and relay workers with the same Compose files used to start them before upgrading or rolling back the core image. The lifecycle commands report any additional writers still running. After validating the core, start the matching optional image and profile one at a time and check job recovery and delivery health.

## HTTPS, live ports, and provider access

Terminate HTTPS at the trusted reverse proxy and expose the public site through it. Bind the CMS HTTP port to loopback. For self-hosted MediaMTX, apply the live compose overlay and expose its gateway through the same HTTPS boundary. Keep MediaMTX API and recording ports 9997 and 9996 private. Open UDP 8189 for the configured ICE host. For LiveKit, use the interactive overlay, keep Redis private, and route signaling through HTTPS to port 7880. Verify TCP 7881 and UDP 7882 from an external network. If using TURN, enable only the listener ports and relay range configured on the TURN server. Test with direct ICE blocked and confirm relay use from browser stats.

Set `WEBHOOK_ALLOWED_ORIGINS`, `CREATOR_TRANSCRIPT_ASSIST_ALLOWED_ORIGINS`, and `CREATOR_DUB_ALLOWED_ORIGINS` to comma-separated exact HTTPS origins as applicable. Include the port when it differs from 443. Production webhooks and BYO HTTP caption and dub providers deny requests when their allowlist is empty. Use a local executable adapter for same-host caption or dubbing work. Restrict provider-connected workers at the network boundary to their required destinations and approved DNS. Enforce those rules outside the shared Compose network and block metadata and unrelated internal addresses.

Rotate a provider credential by pausing the affected queue or destination, installing the new credential through the deployment secret store, restarting its consumers, and verifying one authorized delivery. Revoke the old credential at its issuer and verify it is rejected. Rotate webhook signing secrets at both sender and receiver and confirm signature and replay checks. Follow the applicable application-key rotation process before changing envelope keys used by stored credentials. Record only secret references and rotation times in the incident notes.

## Costs, storage, and alerting

The Studio creator quota counts accepted source upload bytes and upload sessions. Its remaining allowance is separate from volume use. Set `MEDIA_MIN_FREE_BYTES` to reserve free space for other operations. A value of zero disables the check. Staged chunks, upload assembly, and local media object writes check available bytes before writing. This is a point-in-time admission check. Keep volume quotas and alerts for concurrent writers, scratch output, S3, and recording services.

Monitor disk blocks and free inodes for PostgreSQL, staging, permanent media, and live recordings. Alert on low free space, rising oldest-job age, stale worker heartbeats, failed jobs, and readiness errors. Configure infrastructure limits for disk and network use before opening creator intake. Pause affected intake and workers at the operator threshold. Preserve canonical files and pending jobs. Remove expired staging through supported cleanup and prune recordings only after confirming retention, replay references, and backup. Verify playback and a byte checksum after any storage migration.

Reconcile original bytes, retained derivative bytes, heavy processing wall-clock seconds, connected live seconds, delivered bytes, and successfully acknowledged destination outputs separately. Use filesystem or object inventory for retained data, durable processing timestamps for render time, stream state transitions for live time, actual transfer counters for network delivery, and provider receipts for outputs. Report unknown or missing measurements as unavailable. Current application limits cover creator source uploads, configured local free-space reserve, and per-destination relay time and bytes.

The MediaMTX gateway emits `live.gateway.delivery` records for viewer playlists, segments, and replay. Each record includes the host, HTTP status, response body bytes, and request duration. Group successful media transfers by host and kind. Treat denied responses and playlist traffic separately. These records exclude URLs, headers, credentials, and transport overhead. They measure only traffic through this gateway.

Measure the frozen candidate on separate 1 GiB and 2 GiB Linux hosts or limits using only PostgreSQL, web, and the core worker with advanced modules inactive. Capture service peaks, host memory, OOM events, latency, and database responsiveness for idle and concurrent core publishing and password reset. On a separate heavy deployment record the input codec, duration, resolution, worker concurrency, processing time, result bytes, and RSS under synthetic loads. Run the core probes during a heavy job and during a recovery from its failure. Report the actual placement, service versions and limits with each result.

## Live incident and restore

When a stream goes down, check the source connection, room state, gateway readiness, and player separately. Record the room and job IDs and the last observed transitions. Stop or revoke the affected feed through its owning service. Confirm that refreshed tokens and media requests reflect current authorization. A failed external destination may be retried independently after checking for a provider receipt. Keep recordings private pending review. See [Podcast Studio runbooks](../podcast-studio/RUNBOOKS.md) for guest connectivity and render recovery.

Rehearse full backup and restore in an isolated database and media volume following [Operational Backup](../OPERATIONAL_BACKUP.md). Quiesce all writers, including optional media, destination, and account workers. On restore, verify database and media checksums, rights and access policy, signed delivery, and that unprocessed jobs remain resumable. Keep external delivery paused until the restored environment and its provider credentials have been deliberately approved. Promote only after an isolated restore passes.

The operational archive contains PostgreSQL and the application media volume. Back up the optional MediaMTX or LiveKit recording volume and external object storage independently, using their retention and provider procedures. Quiesce their writers before taking those snapshots and verify replay references against the restored volumes.
