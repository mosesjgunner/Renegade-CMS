## How to read this inventory

This is the release source of truth for public feature claims. A Payload collection, route, type, or UI screen is not evidence by itself. `VERIFIED` requires an exercised workflow through persistence and its output boundary. `VERIFIED WITH EXTERNAL PROVIDER REQUIRED` means the local workflow is exercised, but useful production output depends on a configured provider. `DEGRADED BUT SAFE` means the system fails closed or gives a narrower local result. `EXPERIMENTAL` has executable implementation but lacks a realistic end-to-end acceptance test. `CONTRACT ONLY` is schema, policy, adapter, or helper code without a complete workflow. `INCOMPLETE` is a partial workflow. `BROKEN` is an implementation defect that makes the intended workflow unsafe or incorrect. `REMOVED` is intentionally not offered.

The registered repository is `src/modules/payload-domains.ts`: Operations, Identity, Core, Integrations, Editorial, Releases, Media, Social, Network, Audience, Analytics, Experiences, Quality, and Commerce. It is the inventory boundary; historical ideas outside it are not release features.

## Release blockers

1. Do not make public claims for translation workflows, community posting, CRM automation, analytics collection, consent UI, outbound webhooks, live federation, or commerce/crypto/POS/POD. They are not verified end-to-end.
2. Before enabling commerce outside development, add a route-level PostgreSQL acceptance test for checkout initiation → signed webhook → receipt/inventory → duplicate webhook. The confirmed-webhook settlement gap found in this audit was corrected, but has not yet been exercised through the HTTP route.
