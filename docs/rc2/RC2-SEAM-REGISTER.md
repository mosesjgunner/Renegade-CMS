## Seam notes

- **Seam 1:** `src/app/(frontend)/articles/[slug]/page.tsx` is a one-line delegation to the catch-all canonical page — there is exactly one public renderer, which is why theme/layout behavior is uniform. The layout lookup (`page-layouts` find, catch-all ~line 247) and hierarchy resolution (sections/categories/collections by path) all run in that single file.
- **Seam 2:** The NEW-01 history lives here: the command center once queried `media-jobs` on floor installs where the media-studio module was off; the fix was route-side. The floor/studio split (library = floor in `Publishing.ts`; pipeline = factory-built media-studio collections in `src/collections/MediaPublishing.ts`) remains the seam's main comprehension hazard.
- **Seam 3:** Projection coverage follows collection registration — `searchProjectionHooks('products')` in `Commerce.ts`, equivalents in `Community.ts` and others. Anything stored outside Payload collections (seam 6's SQL domain) has no projection path, so comments/messages are structurally unsearchable via the public search seam. Recorded as a caveat, not a defect claim: no scope statement promises comment search.
- **Seam 4:** The saga → social handoff is a direct in-process import (`releases/saga.ts` line 18 imports `executeReleaseDistribution` from `social/release-distribution.ts`), not a queue message — failure semantics therefore live in the saga's own retry/rollback, and the releases service separately creates `social-queue-items` under an execution lock (service.ts ~747–764). Two related but distinct handoff shapes in one seam; both are covered by the release acceptance suite.
- **Seam 5:** The 09D closure is the seam's strongest evidence: the segment evaluator once hardcoded seven selector dimensions empty (segments matched nobody) — found, fixed, and closure-tested (`aud-09d-selector-closure`). Suppression/consent enforcement sits in `src/modules/audience/service.ts` (suppression reads/writes at lines ~304–475) at recipient-build time, so dispatch tasks consume a pre-filtered recipient set.
- **Seam 6:** The SQL domain is bigger than comments: comm-00 (reports/cases/actions), comm-03 (comments), comm-05 (moderation registry), comm-07 (conversations/messages) migrations, with direct INSERTs in `comment-identity.ts`, `conversation-composer.ts`, `moderation-reports.ts`. The trigger in comm_03a (~line 85) rejects a thread whose site disagrees with its content's site — the only seam in the register enforced by the database itself.
- **Seam 7:** `operator-report.ts` composition (lines ~195–282) reads `analytics-events`, `orders`, and rollups for one siteId and computes paid-order counts in the report layer. Nothing in `src/modules/commerce/` emits into `analytics-events` — verified by grep across the commerce module (no analytics references in its service/tasks).
- **Seam 8:** The proxy also feeds `samePublicOrigin` checks (`site-scope.ts` line 81) used by public API routes — host resolution doubles as the origin-trust mechanism for member-facing APIs.
- **Seam 10:** Task registration is by domain aggregation, not by central list: `payload-domains.ts` (line ~89) passes `registrations.tasks` into the lexical/jobs config assembly, and `payload.config.ts` sets `tasks: domainRegistrations.tasks`. A task that no domain registers does not exist at runtime — registration drift would be silent, which is why the A-02 "unreachable agent system" (#60) matters: its functions are registered nowhere.
- **Seam 11:** The registry's own claims are the honesty anchor — commerce: "zero live charges, payouts, or physical orders"; network: "Remote production federation is deferred"; social: "Remote production network dispatches are unconfigured". The seam's problem is not fake success; it is that sandbox-boundedness is uniform, so no seam crossing can currently produce live-provider evidence for the RC3 family gates that will need it.
- **Additional A-02 input — Quality Center gate straddle (admin surface ↔ module gate):** `src/modules/admin/RenderedQualityCenter.tsx` mounts unconditionally in `src/payload.config.ts` while the `quality-*` collections and the `quality-scan` task belong to the optional `quality` module. Same shape as the seam-2 NEW-01 defect. No failure is demonstrated (the surface rendered live in GUI-05C and its API is staff-gated), but floor behavior with `quality` off is unproven — FRICTION (unproven floor behavior), owned by C-03's checklist. Not counted in the 11-seam distribution.
- **Additional A-02 input — gate-label drift:** `docs/rc/CAPABILITY_LEDGER.md` calls telecom and automation-runs "floor"; `src/modules/module-registry.ts` claims them under `newsletter`/`notifications`. The registry governed A-02 and this register; the drift is documentation-only but should be reconciled in A-03's debt register so future audits stop tripping on it.
