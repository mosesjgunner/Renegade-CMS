# RC3-15B: groups & rooms — built and proven at service level (E2 per leg; no E3 claimed)

Branch `rc3-15b` on fetched main `82b5c6c` (the Codex stack Matthew decided to keep). All three room forms from Matthew's Nov 17, 2026 direction are built on the existing chat/messaging durability and moderation machinery: (a) Discord-style persistent chat rooms (site lounge + group rooms), (b) Circle-style group spaces (groups + group home + Library), (c) content-attached live discussion rooms (event-bound rooms). Proof is `tests/integration/rc315b-groups-rooms.integration.test.ts` (18 tests) against real Postgres on the canonical two-site rc2 world, plus `tests/unit/rc3-15b-groups-rooms.test.ts` (9 tests). No leg claims E3: there is no browser/UI leg in this pass — the services are the contract layer, the same posture as RC3-15A/16, and wiring REST routes and pages remains open (named below).

## What was built

- Migration `20261121_170000_rc315b_groups_rooms`: `groups`, `group_memberships`, `group_audit_entries`, `room_bindings`, `room_event_attendees`, `room_read_states`, `room_recaps`, `room_recap_quotes`; SQL functions `room_audience()` and `room_history_floor()`; the `messages_require_active_membership()` trigger gains a derived branch (unbound conversations are structurally unaffected — the function returns no rows for them). `down()` restores the original trigger body verbatim and drops the new objects.
- `src/modules/community/groups.ts`: group CRUD, directory/detail privacy rules, join modes with question/answer validation, invites, join review, role ladder with escalation guards and ownership transfer, group-scoped ban/unban, leave rules, audit reads, and from-join floor materialization on join/approval. The product label lives in exactly one place, `GROUP_PRODUCT_LABEL = 'Circles'` (D1) — **the name is not ratified by Matthew**; a rename is a copy change.
- `src/modules/community/rooms.ts`: the shared audience function (JS + SQL mirrors), room create/attendees/lifecycle, read-state floors and monotonic cursors, cursor polling with block/mute read filtering, the D6 denied-metadata shape, resolved-set containment (`resolveRoomAudienceIds` / `resolveDestinationAudienceIds` / `isAudienceSubset`), recap create/publish/get, Library and group-home projections.
- `src/modules/community/conversation-composer.ts`: send and list gain a derived branch when no roster row exists (rooms); the DM path is unchanged, including pairwise block enforcement — in rooms, pairwise blocks act at read/display per contract §3 while the send gate is audience + standing + sanctions.
- `src/modules/community/moderation-reports.ts`: the CIR-R-09 authorization branch described above.

## Open items at their true level

- **No REST routes, no UI pages** for groups/rooms/recaps — services are the contract layer (E2). A browser journey is unproven; nothing here is E3.
- **COM-GRP-2 not built**: discussions/calendar entries are not yet scoped by `groupId`; the group home covers rooms, activity via rooms, and recaps only.
- **Room notifications/alerts not built** (D8 leaves defaults unimplemented); group join/invite notifications reuse the canonical dispatcher and are covered only to that extent.
- **Entitlement-gated groups (D7) not built**; presence and polls remain out-of-scope expansions per the brief.
- **PT-K1 staff-oversight rule and the "Circles" label are both unratified** working decisions, each isolated to one place for a cheap reversal.
- Process-restart proof for rooms is inherited from the messaging durability proven in earlier passes (same tables, same transaction shape); no separate restart drill was run for the new surfaces.
