## Supporting changes (in the delta, called out honestly)

- **Source descriptor storage:** products gain a `sourcePolicy` JSON field (per-variant descriptors: type, provider key, external ref, observed cost/availability snapshot) and payment intents gain an `fxQuote` JSON field — migration `20261124_090000_rc320_adapter_sources`, registered last in `src/migrations/index.ts`, rehearsed fresh (176 migrations) and on the upgrade path. A dropship relationship is resolved **only** from a reviewed `sourcePolicy` descriptor — an `external-hook` variant without one stays own-inventory; supplier relationships are never inferred.
- **Availability semantics completed:** `checkLineAvailability` had no case for `external-hook` or `affiliate` variants — they fell through to "Unknown inventory policy" and were silently dropped from carts, which made both catalog policies unusable. Both now resolve as available (stock/availability lives with the external party and is enforced via observed evidence at proposal/plan time). No existing test pinned the old drop behavior.
- **Initiate hash/quote scoping:** with a proposal present, the checkout integrity hash and the quoted-line snapshot are computed over the proposal's priced (payable) line set — the same set the order is built from. Non-partitioned flows are unchanged.
- **`payload-types.ts`:** the two new fields were added by hand in the committed file's existing generated style (interface + select entries). A full `generate:types` run was tried and reverted: it also rewrites unrelated pre-existing drift (RC3-19 task entries, older JSON-field renderings) that belongs to the owner's toolchain, not this slice.
