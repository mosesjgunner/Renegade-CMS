# RC3 90-Area Ledger (RC3-00 re-baseline)

Built by RC3-00 (audit-only; no features built, no product code changed).
This is the RC2 90-area ledger re-issued on the RC2 exit tree, with the
post-audit evidence reconciled into the rows. It is the instrument every
later RC3 pass is measured with.

**Baseline pin**

- Tree: `2d4cb3ddf70db5b5f9570297e6bae0d7ff8774bf` — current `main` and
  the `rc2` tag target (the tag and main resolve to the same commit).
- CI at the pin: hosted `verify` completed/success on that exact SHA
  (read via the GitHub API during this pass; see
  `evidence/RC3-00/RESULT.md`).
- Source inventory: `docs/rc2/RC2-90-AREA-LEDGER.md`, audited Nov 11,
  2026 against tree `62d8ece`. Area names, numbers and systems are
  copied **verbatim** from it. The machine-checkable form of this
  ledger is `docs/rc3/RC3-90-AREA-LEDGER.csv` (same rows, parseable;
  the two supplementary rows CF and NEO4J are marked and are not part
  of the 90).

**Method — the no-relabeling rule, applied**

- E-levels follow the governing plan's ladder literally (E0
  concept/stub, E1 mounted useful action with persisted readback or
  verifiable output, E2 connected workflow with scoped permissions and
  a proven negative case, E3 operationally supported, E4 mature).
- **No level was upgraded on inference.** Exactly one upward regrade
  was made in this pass — #5 Complete SEO, E1 → E2 — on executed proof
  that post-dates the RC2 audit (SEO 1.0 pass, PR #95, live probe
  43/43; the same pass closed DEBT-14). Every other row keeps its RC2
  level; where post-audit work materially advanced a row's evidence
  without completing its deciding proof (#10, #15), the row is
  annotated and marked stale instead of regraded.
- Split rows keep their parts: #16 (video E1 / livestreams E0), #59
  (SEO-suggestion path E2 / wider catalog E1), #74 (REST E2 / GraphQL
  NOT VERIFIED). Per the RC3 contract, the weakest required
  sub-capability is the row's floor; the CSV carries both the display
  level and the floor.
- Provider status is recorded independently of E-level (sandbox,
  harness-only, test-mode, unconfigured, held). A provider-blocked
  workflow keeps that status until it is measured.
- Owning passes use the RC3 pass numbering adopted Nov 20, 2026
  (00/00A baseline, 01–07 Wave 1, 08–16 Wave 2, 17–23 Wave 3, 24–25
  freeze/exit). Every one of the 90 rows has a primary owning pass;
  passes 00, 00A, 24 and 25 own the whole ledger rather than single
  rows and are not repeated per row.

## Standing facts vs owner decisions

**Standing facts** (settled; later passes build on them):

- Member standing is model C — one identity, per-site standing —
  decided Nov 12, 2026. The join route and standing service shipped
  in I-02 (PR #84).
- License: AGPL-3.0 (settled Nov 16, 2026). Working managed-hosting
  license model adopted Nov 20, 2026: the core stays free to run;
  selling it as a managed service under the Renegade name or with
  Renegade's machinery is licensed per active client/site.
- Grammar's engine is Harper — bundled, built-in, NOT BYO-model
  (decided Nov 11, 2026).
- Podcasting's audio-correction chain is all-local (open-source
  engines, no cloud enhance APIs), decided Nov 18, 2026.
- Rooms are wanted in all three forms (chat rooms, group spaces,
  content-attached live rooms), owner's word Nov 17, 2026.
- POD-RC-01's verdict stands at HOLD: the feed work is merged and
  proven locally; the Spotify, Apple and named-client legs are
  unproven until a public HTTPS host with the owner's accounts
  exists.
- Neo4j is architecture, not a feature: Postgres is canonical, Neo4j
  is a graph projection, and it does not fit the Lean profile.

**Owner decisions — open, recorded, not decided by this pass:**

1. **Posting-gate enforcement flip.** Model C is decided; refusing
   posts on never-joined sites is not yet behavior. The flip is the
   owner's separate explicit call (rows #37, #41).
2. **Profile automatic at signup vs public Space opt-in.** Record
   shape is settled (DEBT-01); creation policy is not (row #38).
3. **Email.** Live sending and the whole email direction are HELD
   pending the owner's own research (Nov 18, 2026). RC3-07 is
   fixture-only until he authorizes real legs (row #29).
4. **Public provider submissions** (podcast directories, social
   networks, any live provider) — each needs the owner's
   authorization in its own scope (rows #15, #26, #29, #31).
5. **Managed-hosting terms** — the working model is adopted; legal
   drafting and any public terms are future work on the owner's word
   (row #78).
6. **Custom-fields ranking** — filed as an RC3 candidate Nov 14,
   2026; where it ranks is the owner's call at RC3 planning
   (supplementary row CF).
7. **The POD-RC-01 record wording** — the `rc2` tag's tree contains
   PR #113 while the published release notes describe POD-RC-01 as
   not part of RC2. A corrected text is drafted for owner review in
   `evidence/RC3-00/POD-RC-01-RECORD-FLAG.md`. No public edit is made
   by this pass.
