# Repository-supported shared contracts

These are the existing repository contracts frozen for Phase A coordination. A statement marked **MUST BE FROZEN BY A-XX** is intentionally unresolved; no card may fill it by implication.

| Concern | Frozen repository-supported contract | Evidence |
| --- | --- | --- |
| Canonical content identity | PostgreSQL/Payload UUID is the canonical identity. `content` and `article-family-content` are canonical content records; public presentation is a projection, never a replacement store. | `docs/execution/five-phase-baseline/DEPENDENCY_MAP.md`; `docs/architecture/canonical-information-architecture.md` |
| Page/post body and revisions | Owning content/editorial records retain body and revision/provenance truth; `revision-records` represents retained historical revisions. A renderer, theme, provider, or layout does not own it. **MUST BE FROZEN BY A-01** for any unresolved Page-versus-Post body/revision detail. | `src/collections/Publishing.ts`; `docs/architecture/project-spine.md` |
| Canonical paths and redirects | Scoped canonical paths are owned by publishing/taxonomy records. `taxonomy-redirects` records taxonomy move history; site-scoped `public-redirects` owns public URL redirects. A redirect cannot target itself. | `src/collections/Publishing.ts`; `docs/architecture/canonical-information-architecture.md` |
| Media assets and usages | `media-assets` owns reusable byte/storage records; `media-usages` describes references. Albums/content reuse assets and do not duplicate a competing byte store. | `docs/architecture/canonical-information-architecture.md`; `src/collections/Publishing.ts` |
| Storage | Local storage is the default. The optional S3 adapter is a configuration seam and incomplete non-production S3 falls back to local; providers do not become canonical storage. | `src/modules/core/config.ts`; `src/collections/Publishing.ts` |
| Site/publication/space scope | `sites` is the installation boundary; publications belong to a site and spaces/member-owned publications use explicit relationships. Publication and space scope can be nullable; never infer scope from a singleton, URL, slug, or provider account. | `docs/architecture/canonical-information-architecture.md`; `src/collections/canonical-shared.ts` |
| Draft/public visibility | Direct public views require `canRenderPublic`; discovery requires `canDiscoverPublic`. Non-public, non-published, held, suspended, burned/tombstoned, expired, and unlisted-as-discovery content is excluded per those gates. | `docs/architecture/public-rendering-contract.md`; `src/modules/public` |
| Public media eligibility | Public media must pass the owning public projection/visibility gate and must not disclose private source/provenance or an ineligible asset through a usage. **MUST BE FROZEN BY A-03** for the exact eligibility predicate. | `docs/architecture/public-rendering-contract.md`; `docs/architecture/media-publication-contract.md` |
| Publication navigation | Navigation/layout is a scoped presentation projection over `page-layouts`, taxonomy, and canonical paths; it does not own or mutate canonical content. **MUST BE FROZEN BY A-04** for the publication-navigation write owner. | `docs/execution/five-phase-baseline/DEPENDENCY_MAP.md`; `docs/architecture/page-builder-sdk.md` |
| Site Settings SEO inheritance | `site-settings` owns defaults and `inheritancePolicy`; typed SEO precedence is manual then generated. Publication/brand/page inheritance follows explicit policy; raw structured data is owner-only. | `src/globals/SiteSettings.ts`; `docs/architecture/public-rendering-contract.md` |
| Operational backup vs portable export | Operational backup/restore is deployment recovery with PostgreSQL/runtime storage; portable export is the separately owned portability boundary. Neither substitutes for the other. **MUST BE FROZEN BY A-08** for retention, portability and restore compatibility details. | `package.json`; `docs/tasks/m02-platform-operations/README.md`; `docs/architecture/extension-sdk.md` |
| Architecture | One Next.js App Router/Payload modular monolith using Payload’s PostgreSQL adapter and registered Payload domains/jobs. No parallel runtime, generic event bus, competing identity store, or second architecture. | `src/payload.config.ts`; `docs/execution/five-phase-baseline/README.md` |
| Deployment profile | Lean and Standard are the small-to-start profiles. Lean hides/queues/delegates constrained capabilities without deleting data or changing ownership; Standard remains a supported configuration profile. | `src/modules/core/config.ts`; `src/globals/SiteSettings.ts`; `docs/architecture/extension-sdk.md` |
